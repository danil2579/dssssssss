# Техническое устройство

## Стек

| | |
|---|---|
| Движок | **Godot 4.7.x**, стандартная сборка (не .NET) |
| Язык | GDScript со статической типизацией |
| Рендер | Forward+ (если на слабых ноутбуках будут проблемы — переключить на Mobile или Compatibility: Project Settings → Rendering → Renderer) |

| Голос | Steam Voice через GodotSteam или отдельный VoIP-аддон (решаем на этапе 2) |
| Модели | glTF (.glb) из Blender |

## Сетевая модель

**Хост решает всё (host-authoritative), клиенты слушаются.**

- **Игроки:** каждый управляет своим вором сам (он владелец, multiplayer authority) и 20 раз в секунду рассылает позицию. Остальные плавно подтягивают модель (`player.gd → _net_state`).
- **Спавн** (`test_museum.gd`): клиент загружает уровень и сообщает хосту `_client_ready`. Хост создаёт его вора у всех, присылает ему уже существующих игроков и состояние объектов (журнал мазков холстов).
- **`Net.in_level`** — список тех, кто уже загрузил уровень. Все RPC объектам уровня шлём через `Net.send_to_level(obj, "метод", [аргументы])`, иначе у загружающегося игрока будет ошибка «node not found».
- **Холст:** мазок — это маленький словарь `{pts, c, r}`. Его применяют у себя и рассылают остальным, все рисуют одинаково (детерминированно). Хост хранит журнал мазков для опоздавших.
- **Физика (этап 1–2):** физические предметы (рамы, вазы) симулирует **только хост** и рассылает их позиции. Клиент, который «несёт» предмет, отправляет хосту намерение (куда тянет), а не позицию.
- **Охрана (этап 1):** ИИ охранников работает только на хосте, клиентам приходят позиции, анимации и уровень подозрения.

### Переход на Steam (этап 2)
1. Поставить GodotSteam. Есть два варианта: готовая сборка редактора Godot со встроенным Steam (проще) или GDExtension-плагин. Брать версию, совместимую с нашей версией Godot (см. releases GodotSteam).
2. До получения своего App ID тестировать с **App ID 480** (тестовое приложение Valve «Spacewar»).
3. В `net.gd` добавить `host_steam()` и `join_steam(lobby_id)` с `SteamMultiplayerPeer` вместо `ENetMultiplayerPeer`. **Остальной код не меняется** — он работает через стандартный `multiplayer` API.
4. Меню: «Создать лобби», «Пригласить друзей» (оверлей Steam), вход по приглашению.

## Оценка подделки

`scripts/forgery/forgery_judge.gd`:
1. Оригинал и подделка уменьшаются до сетки 12×12 (усреднение цветов).
2. Считается среднее расстояние цветов по клеткам → «сходство» от 0 до 1.
3. Сходство переводится в проценты через пороги `LOW`/`HIGH`. Пустой холст и каракули дают 0%, аккуратная копия крупными пятнами — 70–100%.

Позже: сетка мельче при проверке вблизи (эксперт), учёт освещения, бонус за «узнаваемые детали» (лицо в нужном месте).

## Соглашения по коду

- Статическая типизация везде, где можно (`var x: int`, `-> void`).
- Имена: `snake_case` для файлов, переменных и функций, `PascalCase` для классов и узлов.
- RPC-методы начинаются с `_rpc_` или `_net_`, у каждого явно указаны режимы (`@rpc("any_peer", "call_remote", "reliable")`).
- Комментарии и тексты в игре пока на русском. Перед релизом все строки выносятся в переводы (Godot Localization, CSV или PO) — RU и EN обязательно, дальше по желанию (китайский, португальский, немецкий, испанский — крупные рынки Steam).
- Новая механика — новый скрипт и сцена. Не раздуваем `player.gd`.

## Тесты

Запускать перед каждым коммитом (из папки `poddelka`):

```bash
# 1. Одиночный дымовой тест: уровень, игрок, рисование, оценка, подмена
godot --headless --path game res://tests/smoke_test.tscn

# 2. Сетевой тест: хост + клиент на одном компьютере (два терминала)
godot --headless --path game res://tests/net_test.tscn -- --net-test-host
godot --headless --path game res://tests/net_test.tscn -- --net-test-join
```

В Windows вместо `godot` укажи путь к exe, например `"C:\Godot\Godot_v4.7.2-stable_win64_console.exe"` (версия *console* печатает вывод в терминал).

Ручная проверка мультиплеера в редакторе: **Debug → Customize Run Instances… → Enable Multiple Instances → 2–4**, затем F5. В одном окне «Создать игру», в остальных «Подключиться» (127.0.0.1).

Быстрый запуск без меню: `godot --path game -- --host` и `godot --path game -- --join 127.0.0.1`.

## Производительность (цели)

- 60 FPS на ноутбуке со встроенной графикой (Intel Iris Xe / AMD Radeon 680M) в 1080p.
- До 4 игроков, до 6 охранников, до 30 физических объектов на уровне.
- Холст 256×256: мазок рисуется на процессоре, а текстура обновляется раз в кадр (`ForgeryCanvas.flush`).

## Сборка и выпуск

1. Editor → Manage Export Templates → скачать шаблоны для 4.7.x.
2. Project → Export → Windows Desktop (плюс Linux для Steam Deck).
3. Загрузка в Steam через SteamPipe (steamcmd или ContentBuilder из Steamworks SDK). Подробно — на этапе 4.
